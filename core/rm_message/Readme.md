# RMMessage

这是一个裁判系统通信msg定义

### 一、 协议统一帧头（Frame Header）
所有串口通信帧必须遵循以下 5 字节的起始结构：

| 字节偏移 | 域 | 大小 | 详细描述 |
| :--- | :--- | :--- | :--- |
| 0 | **SOF** | 1-byte | 数据帧起始字节，固定值为 `0xA5` |
| 1 | **data_length** | 2-byte | 数据段（data）的字节长度 |
| 3 | **seq** | 1-byte | 包序号 |
| 4 | **CRC8** | 1-byte | 帧头校验值 |

---

### 二、 比赛基础信息类（CMD ID: 0x000x）

#### 1. 比赛状态数据 (Game Status) - `0x0001`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 全体机器人
*   **Data段长度：** 11-byte
*   **详细定义：**
    *   **Byte 0:**
        *   **bit 0-3:** 比赛类型 (1:超级对抗赛, 2:高校单项赛, 3:ICRA, 4:联盟赛3V3, 5:联盟赛步兵对抗)
        *   **bit 4-7:** 当前比赛阶段 (0:未开始, 1:准备阶段, 2:自检, 3:5s倒计时, 4:比赛中, 5:结算中)
    *   **Byte 1-2:** 当前阶段剩余时间（秒）
    *   **Byte 3-10:** UNIX 时间戳（机器人连接NTP服务器后生效）

#### 2. 比赛结果数据 (Game Result) - `0x0002`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 全体机器人
*   **Data段长度：** 1-byte
*   **详细定义：**
    *   **Byte 0:** 0:平局, 1:红方胜利, 2:蓝方胜利

#### 3. 机器人血量数据 (Robot HP) - `0x0003`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 全体机器人
*   **Data段长度：** 16-byte
*   **详细定义（每项 2-byte, uint16_t）：**
    *   Byte 0-1: 己方1号英雄血量；Byte 2-3: 2号工程血量；Byte 4-5: 3号步兵血量；Byte 6-7: 4号步兵血量；Byte 8-9: 保留；Byte 10-11: 7号哨兵血量；Byte 12-13: 前哨站血量；Byte 14-15: 基地血量。

### 三、 场地与裁判类（CMD ID: 0x010x）

#### 4. 场地事件数据 (Field Events) - `0x0101`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 己方全体机器人
*   **Data段长度：** 4-byte（32-bit位映射）
*   **详细位定义（Byte 0-3）：**
    *   **bit 0:** 己方与资源区不重叠的补给区占领状态 (1:已占领)
    *   **bit 1:** 己方与资源区重叠的补给区占领状态 (1:已占领)
    *   **bit 2:** 己方补给区占领状态 (仅RMUL)
    *   **bit 3-4:** 己方小能量机关状态 (0:未激活, 1:已激活, 2:正在激活)
    *   **bit 5-6:** 己方大能量机关状态 (0:未激活, 1:已激活, 2:正在激活)
    *   **bit 7-8:** 己方中央高地占领状态 (1:被己方占领, 2:被对方占领)
    *   **bit 9-10:** 己方梯形高地占领状态 (1:已占领)
    *   **bit 11-19:** 对方飞镖最后击中己方前哨站/时间 (0-420s)
    *   **bit 20-22:** 对方飞镖最后击中的目标 (1:前哨站, 2:基地固定, 3:基地随机固定, 4:基地随机移动, 5:基地末端移动)
    *   **bit 23-24:** 中心增益点占领状态 (仅RMUL)
    *   **bit 25-26:** 己方堡垒增益点占领状态 (0:未占领, 1:己方占领, 2:对方占领, 3:双方占领)
    *   **bit 27-28:** 己方前哨站增益点占领状态
    *   **bit 29:** 己方基地增益点占领状态
    *   **bit 30-31:** 保留

#### 5. 裁判警告数据 (Referee Warning) - `0x0104`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 被判罚方全体机器人
*   **Data段长度：** 3-byte
*   **详细定义：**
    *   **Byte 0:** 判罚等级 (1:双方黄牌, 2:黄牌, 3:红牌, 4:判负)
    *   **Byte 1:** 犯规机器人 ID (如红1为1, 蓝1为101)
    *   **Byte 2:** 对应判罚等级的违规次数

#### 6. 飞镖发射相关数据 (Dart Info) - `0x0105`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 己方全体机器人
*   **Data段长度：** 3-byte
*   **详细位定义：**
    *   **Byte 0:** 己方飞镖发射剩余时间（秒）
    *   **Byte 1-2 (bit段):**
        *   **bit 0-2:** 最近一次击中目标类型 (1-5同0x0101)
        *   **bit 3-5:** 对方最近被击中累计次数 (0-4次)
        *   **bit 6-7:** 飞镖此时选定的打击目标 (0:前哨站/未选, 1:基地固定, 2:基地随机固定, 3:随机移动, 4:末端移动)
        *   **bit 8-15:** 保留

### 四、 机器人状态类（CMD ID: 0x020x）

#### 7. 机器人性能体系数据 (Robot Status) - `0x0201`
*   **发送方：** 主控模块（裁判系统模块） $\rightarrow$ 对应机器人
*   **Data段长度：** 13-byte
*   **详细定义：**
    *   **Byte 0:** 本机器人 ID；**Byte 1:** 等级；**Byte 2-3:** 当前血量；**Byte 4-5:** 血量上限
    *   **Byte 6-7:** 射击热量冷却值/s；**Byte 8-9:** 热量上限；**Byte 10-11:** 底盘功率上限
    *   **Byte 12 (电源输出状态位):**
        *   **bit 0:** gimbal 口输出状态 (1: 24V输出)
        *   **bit 1:** chassis 口输出状态
        *   **bit 2:** shooter 口输出状态
        *   **bit 3-7:** 保留

#### 8. 实时底盘缓冲与热量 (Buffer & Heat) - `0x0202`
*   **发送方：** 主控模块（裁判系统模块） $\rightarrow$ 对应机器人
*   **Data段长度：** 14-byte
*   **详细定义：**
    *   Byte0-7: Reserved；Byte 8-9: 缓冲能量 (J)；Byte 10-11: 17mm发射机构热量；Byte 12-13: 42mm发射机构热量。

#### 9. 机器人位置数据 (Position) - `0x0203`
*   **发送方：** 主控模块（裁判系统模块） $\rightarrow$ 对应机器人
*   **Data段长度：** 16-byte
*   **详细定义：**
    *   Byte 0-3: x 坐标 (float, m)；Byte 4-7: y 坐标 (float, m)
    *   Byte 8-11: 测速模块朝向 (float, 度, 正北为0)

#### 10. 机器人增益与能量反馈 (Robot Buffs) - `0x0204`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 对应机器人
*   **Data段长度：** 8-byte
*   **详细位定义：**
    *   Byte 0: 回血增益 (%)；Byte 1-2: 冷却增益 (x/s)；Byte 3: 防御增益 (%)；Byte 4: 负防御增益 (%)；Byte 5: 攻击增益 (%)
    *   **Byte 6 (能量反馈位):**
        *   **bit 0-6:** 剩余能量比例 (bit0:≥125%, bit1:≥100%, bit2:≥50%, bit3:≥30%, bit4:≥15%, bit5:≥5%, bit6:≥1%)
        *   **bit 7:** 默认 0

#### 11. 伤害状态数据 (Hurt Event) - `0x0206`
*   **发送方：** 主控模块（裁判系统模块） $\rightarrow$ 对应机器人
*   **Data段长度：** 1-byte
*   **详细位定义：**
    *   **Byte 0:**
        *   **bit 0-3:** 扣血装甲板/测速模块 ID (0:其他, 1-4:装甲, 5:测速)
        *   **bit 4-7:** 血量变化类型 (0:装甲受击, 1:模块离线, 5:受到撞击)

#### 12. 实时射击数据 (Shoot Data) - `0x0207`
*   **发送方：** 主控模块（裁判系统模块） $\rightarrow$ 对应机器人
*   **Data段长度：** 7-byte
*   **详细定义：**
    *   **Byte 0 (弹丸类型):** bit 1: 17mm, bit 2: 42mm
    *   **Byte 1 (发射机构):** 1: 17mm机构, 3: 42mm机构
    *   **Byte 2:** 射速 (Hz)；**Byte 3-6:** 初速度 (float, m/s)

#### 13. 允许发弹量 (Ammo Allowance) - `0x0208`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 己方英雄/步兵/哨兵/空中
*   **Data段长度：** 6-byte
*   **详细定义：**
    *   Byte 0-1: 17mm允许发弹量；Byte 2-3: 42mm允许发弹量；Byte 4-5: 剩余金币数量

#### 14. 机器人 RFID 状态 (RFID Status) - `0x0209`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 己方装有RFID的机器人
*   **Data段长度：** 5-byte
*   **详细位定义（Byte 0-3, 每一位代表一个位置检测卡）：**
    *   bit 0: 基地增益点；bit 1/2: 己/方中央高地；bit 3/4: 己/方梯形高地；bit 5-8: 地形跨越(飞坡)；bit 9-12: 地形跨越(中央高地)；bit 13-16: 地形跨越(公路区)；bit 17: 堡垒；bit 18: 前哨站；bit 19: 补给区；bit 20-31: 隧道、装配增益点等。

#### 15. 飞镖选手端指令 (Dart Cmd) - `0x020A`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 己方飞镖机器人
*   **Data段长度：** 6-byte
*   **详细定义：**
    *   Byte 0: 飞镖站状态 (1:关闭, 2:开启中, 0:已开启)
    *   Byte 2-3: 切换击打目标倒计时；Byte 4-5: 最后发射指令倒计时

#### 16. 地面机器人位置 (Ground Positions) - `0x020B`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 己方哨兵机器人
*   **Data段长度：** 40-byte
*   **详细定义：** 己方英雄、工程、3/4号步兵的坐标 (float x, y)。

#### 17. 雷达标记进度 (Radar Mark) - `0x020C`
*   **发送方：** 裁判系统服务器 $\rightarrow$ 己方雷达机器人
*   **Data段长度：** 2-byte
*   **详细定义：** bit 0-5 对应对方/己方机器人易伤/特殊标识状态。

#### 18. 哨兵/雷达决策信息 (Decision Info)
*   **哨兵指令 (0x020D):**
    *   **发送方：** 裁判系统服务器 $\rightarrow$ 己方哨兵机器人
    *   **Byte 0-3 bit段:** bit 0-10: 允许发弹量；bit 11-14: 远程兑换次数；bit 19: 免费复活可用；bit 20: 立即复活可用。
    *   **Byte 4 bit段:** bit 12-13: 哨兵姿态 (1:攻击, 2:防御, 3:移动)；bit 14: 能量机关可激活状态。
*   **雷达指令 (0x020E):**
    *   **发送方：** 裁判系统服务器 $\rightarrow$ 己方雷达机器人
    *   **bit 0-1:** 双倍易伤机会 (0-2)；**bit 2:** 对方是否易伤 (1:是)；**bit 3-4:** 己方加密等级。

### 五、 交互数据与图传类（CMD ID: 0x030x）

#### 19. 机器人交互数据 (Robot Interaction) - `0x0301`
*   **发送方：** 机器人 $\rightarrow$ 服务器（转发） $\rightarrow$ 机器人/选手端
*   **结构：** 子内容 ID (2-byte) + 发送者 ID (2-byte) + 接收者 ID (2-byte) + 内容数据段。
*   **绘图子内容配置详细位 (适用于 0x0101-0x0104 图形数据段)：**
    *   **发送路径：** 机器人 $\rightarrow$ 选手端
    *   **图形配置位 (Byte 3-6 中的 bit段):**
        *   **bit 0-2:** 图形操作 (0:空, 1:增加, 2:修改, 3:删除)
        *   **bit 3-5:** 图形类型 (0:直线, 1:矩形, 2:正圆, 3:椭圆, 4:圆弧, 5:浮点, 6:整型, 7:字符)
        *   **bit 6-9:** 图层数 (0-9)
        *   **bit 10-13:** 颜色 (0:红/蓝, 1:黄, 2:绿, 3:橙, 4:紫红, 5:粉, 6:青, 7:黑, 8:白)

#### 20. 自定义控制器交互数据 (Custom Controller) - `0x0302`
*   **发送方：** 自定义控制器 $\rightarrow$ 选手端图传 $\rightarrow$ 机器人
*   **Data段长度：** 30-byte
*   **详细定义：** 30 字节自定义数据。

#### 21. 选手端小地图交互数据 (Map Downlink) - `0x0303`
*   **发送方：** 选手端 $\rightarrow$ 服务器 $\rightarrow$ 己方机器人
*   **Data段长度：** 15-byte
*   **详细定义：**
    *   Byte 0-3: 目标X (float)；Byte 4-7: 目标Y (float)；Byte 8: 键值；Byte 9: 对方ID；Byte 10-11: 来源ID

#### 22. 键鼠遥控数据 (Remote Control) - `0x0304`
*   **发送方：** 选手端 $\rightarrow$ 图传链路 $\rightarrow$ 机器人
*   **Data段长度：** 12-byte
*   **详细位定义：**
    *   Byte 0-1: 鼠标X速；Byte 2-3: 鼠标Y速；Byte 4-5: 滚轮速；Byte 6: 左键(1:按)；Byte 7: 右键
    *   **Byte 8-9 (键盘位掩码):** bit 0:W, 1:S, 2:A, 3:D, 4:Shift, 5:Ctrl, 6:Q, 7:E, 8:R, 9:F, 10:G, 11:Z, 12:X, 13:C, 14:V, 15:B

#### 23. 小地图接收雷达数据 (Radar Map Uplink) - `0x0305`
*   **发送方：** 雷达 $\rightarrow$ 服务器 $\rightarrow$ 己方选手端
*   **Data段长度：** 24-byte
*   **详细定义：** 依次为英雄、工程、3/4/5步兵、哨兵的坐标 (uint16_t, cm)。

#### 24. 非链路模拟键鼠 (Key-Mouse Simulation) - `0x0306`
*   **发送方：** 自定义控制器 $\rightarrow$ 选手端
*   **Data段长度：** 8-byte
*   **详细位定义：**
    *   **Byte 0-1 (键盘值):** bit 0-7: 按键1值, bit 8-15: 按键2值
    *   **Byte 2-3 (鼠标X坐标):** bit 0-11: X像素坐标 (0-1920)；**bit 12-15:** 鼠标左键状态 (1:按下)
    *   **Byte 4-5 (鼠标Y坐标):** bit 0-11: Y像素坐标 (0-1080)；**bit 12-15:** 鼠标右键状态 (1:按下)

#### 25. 小地图路径数据 (Path Uplink) - `0x0307`
*   **发送方：** 哨兵/半自动机器人 $\rightarrow$ 对应选手端
*   **Data段长度：** 103-byte
*   **详细定义：** 意图 (1:攻, 2:守, 3:移)；起点X, Y；X轴增量数组 (49字节)；Y轴增量数组 (49字节)。

#### 26. 小地图自定义信息 (Custom String) - `0x0308`
*   **发送方：** 己方机器人 $\rightarrow$ 己方选手端
*   **Data段长度：** 34-byte
*   **详细定义：** 发送者 ID (2-byte)；接收者 ID (2-byte)；30字节 UTF-16 字符串。

#### 27. 机器人发送自定义数据 - `0x0309 / 0x0310`
*   **0x0309:**
    *   **发送方：** 己方机器人 $\rightarrow$ 对应操作手连接的自定义控制器
    *   **Data段长度：** 30-byte
*   **0x0310:**
    *   **发送方：** 己方机器人 $\rightarrow$ 图传链路 $\rightarrow$ 自定义客户端
    *   **Data段长度：** 150-byte

### 六、 系统信道管理类 (VTM Config)

#### 28. 图传出图信道设置 (Set VTM Channel) - `0x0F01`
*   **发送方：** 机器人 $\rightarrow$ 图传发送端
*   **Data段定义：**
    *   **发送段:** 1-byte, 设置值 1-6 代表信道 1-6。
    *   **接收反馈:** 0: 成功, 1: 启动中无法设置, 2: 设置有误。

#### 29. 查询图传信道 (Query VTM Channel) - `0x0F02`
*   **发送方：** 机器人 $\rightarrow$ 图传发送端
*   **反馈定义：** 0: 未设置, 1-6: 当前运行信道。
